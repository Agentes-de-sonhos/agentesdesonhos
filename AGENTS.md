# Architecture rules
- Public flight/hotel cards and opt-in styles are public-only. Why: preserves admin, other services and secure access.
- Magic Kingdom maps mount on demand in an accessible same-origin iframe; image URLs use CDN pointers and Escape validates origin and source. At 100% the frame follows the full main-column width and natural image height, with vertical scrolling owned by the iframe document; only zoomed navigation constrains height to the initial natural frame, and the desktop sidebar keeps its own contained list. Why: height containment shrank the approved map.
- All additional parks share one static engine with category-scoped IDs, optional original references and independent anchors; selection highlights all anchors. Source groups stay grouped; mixed music/dining venues use one restaurant entry with music subtype. Hotel dining may group at its confirmed location without reusing hotel numbers. Named-only places use symbols; illegible references are documented, never guessed. Rasters keep native pixels; vector PDFs use ICC-managed lossless high-resolution PNGs. Keep full pages when crops would remove geography or tour insets. Secure park-specific close messages preserve the layout; Magic Kingdom stays independent. Why: no invented pins or overlapping entries.
- Orlando editorial photo gallery is added at the public tickets route only for an explicit hostname allowlist (Destinos com a Ju, 100 Limites), outside the shared wizard; its photographs use CDN pointers with official-source credit. Why: preserves wizard and other tenants.
- Tenant hero variants, photo-above campaigns and visited-destination strips use shared opt-in components with safe defaults and scoped preview styles. Why: tenant isolation, no engine duplication.
- ADS briefing e-mail: server-to-server Edge Function `ads-briefing-email` with relay-token auth (SHA-256 in private `ads_briefing_integration`), service-role-only queue + run tables; retries piggyback on the `product-landing-lead-emails` cron. Why: owner-only internal trigger, no public/tenant surface.
- ADS site previews use path-keyed local fixtures on synthetic hostnames and the shared white-label renderer, gated to technical preview hosts with commercial actions and backend access blocked. Why: review without publishing or touching tenant data.
- Sale contract templates embed dynamic fields inside fixed legal text via `agency_contract_templates.render_config` (mode `slotted`, tokens resolved by `src/lib/contractSlots.ts`); literal agency text lives in `src/lib/contractTemplates/*`. Why: one generic engine for every agency; legal text exactly as written.
- SiteLab Base presentation (sections/themes + prospect identity) lives per browser in localStorage (`src/lib/sitelabPresentation.ts`), edited at `/sitelab-base/gestao/apresentacao`, applied only when `profile.demo`. Why: `sitelab_templates` writes are platform-admin-only and the lab panel rejects admins.
- Official US B1/B2 visa data lives in single-row public table `us_visa_public_info` (updated by an external scheduled ChatGPT task, no in-app cron), consumed only opt-in via `useUsVisaPublicInfo` / `UsVisaOfficialInfo`. Why: one shared official source, never auto-enabled.
- The 100 Limites DMC portfolio is one landing (`/dmc-portugal`, `DmcPortugalLandingPage`) routed only for the `editorialDmc` profile; legacy portfolio paths redirect to its anchors in `AgencyDomainRoutes` while their declarative content stays in `agencySiteContentPages`. Why: single B2B page without breaking old links or touching other tenants.
- Site → Blog is an opt-in per-agency module gated by entitlement `site_blog` + permission `site.blog.manage` (RLS `blog_can_manage`); status/published versions change only through SECURITY DEFINER `blog_post_action`/`blog_run_scheduled`; public reads go only through the `public-blog` Edge Function (published or due-scheduled snapshot, private media signed per post). Why: strong tenant isolation; no partial autosave leaks to visitors.
- New ADS presentations use content-complete `buildGoldStandardProfile`, reference profiles and `docs/padrao-ouro-sites.md`; continuity pages stay in allowlisted synthetic fixtures with backend blocked. Why: complete reviews without invented production facts or changed tenants.
- White-label CTA hover is action-specific: WhatsApp buttons may shift to WhatsApp green (`wl-visa-cta`); request pop-up buttons keep brand yellow (`wl-visa-proposal`). Why: green promises an instant handoff a form does not deliver.
- Update prompt (`useAppVersion`) shows once per user only while flag `app_update_prompt` targets a version other than the running bundle (set via SQL after release). Why: owner-controlled.
- Bardelli official profile reuses the gold-standard baseline without presentation/demo or unconfirmed blocks, palette via scoped `wl-bardelli-official`; go-live only in `agencySiteStatus`. Why: real tenant never inherits illustrative content.
- Wallet modules resolve in SQL (trip > owning agency via `wallet_agency_owner` > system); panel uses `get_trip_agency_wallet_defaults`. Why: same agency.
