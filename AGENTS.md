# Architecture rules
- Campaign stage-one previews mount before tenant/auth providers, use existing local agency identity and shared header/footer, and allow only the exact technical preview host plus explicit tenant context; campaign actions/filtering remain local. Why: no live-domain exposure or CRM/network side effects, without modifying existing agency routes.
- Flight/hotel cards and opt-in styles: public-only. Why: protects admin, other services and secure access.
- Magic Kingdom maps: on-demand same-origin iframe, CDN image pointers, origin-checked Escape; at 100% full column width and natural height (iframe owns scroll). Why: height containment shrank the approved map.
- Other parks share one static engine: category-scoped IDs, independent anchors (all highlighted), no guessed pins, native-pixel/lossless maps, full pages kept. Why: no invented pins or overlapping entries.
- Orlando editorial gallery: public tickets, allowlisted Ju/100 Limites hosts only, outside wizard; CDN pointers with official credits. Why: tenant isolation.
- Tenant hero variants, photo-above campaigns and visited strips use shared opt-in components, safe defaults and scoped preview styles. Why: tenant isolation, no duplicated engine.
- ADS briefing e-mail: server-to-server Edge Function `ads-briefing-email` with relay-token auth (SHA-256 in private `ads_briefing_integration`), service-role-only queue + run tables; retries piggyback on the `product-landing-lead-emails` cron. Why: owner-only internal trigger, no public/tenant surface.
- ADS previews: path-keyed local fixtures, synthetic hostnames, shared white-label renderer; technical hosts only, commercial actions/backend blocked. Why: review without touching tenants.
- Sale contract templates embed dynamic fields inside fixed legal text via `agency_contract_templates.render_config` (mode `slotted`, tokens resolved by `src/lib/contractSlots.ts`); literal agency text lives in `src/lib/contractTemplates/*`. Why: one generic engine for every agency; legal text exactly as written.
- SiteLab Base presentation (sections/themes + prospect identity) lives per browser in localStorage (`src/lib/sitelabPresentation.ts`), edited at `/sitelab-base/gestao/apresentacao`, applied only when `profile.demo`. Why: `sitelab_templates` writes are platform-admin-only and the lab panel rejects admins.
- Official US B1/B2 visa data lives in single-row public table `us_visa_public_info` (updated by an external scheduled ChatGPT task, no in-app cron), consumed only opt-in via `useUsVisaPublicInfo` / `UsVisaOfficialInfo`. Why: one shared official source, never auto-enabled.
- The 100 Limites DMC portfolio is one landing (`/dmc-portugal`, `DmcPortugalLandingPage`) routed only for the `editorialDmc` profile; legacy portfolio paths redirect to its anchors in `AgencyDomainRoutes` while their declarative content stays in `agencySiteContentPages`. Why: single B2B page without breaking old links or touching other tenants.
- Site → Blog is an opt-in per-agency module gated by entitlement `site_blog` + permission `site.blog.manage` (RLS `blog_can_manage`); status/published versions change only through SECURITY DEFINER `blog_post_action`/`blog_run_scheduled`; public reads go only through the `public-blog` Edge Function (published or due-scheduled snapshot, private media signed per post). Why: strong tenant isolation; no partial autosave leaks to visitors.
- New ADS presentations use complete `buildGoldStandardProfile`, reference profiles and `docs/padrao-ouro-sites.md`; continuity uses allowlisted synthetic fixtures with backend blocked; editorial/photo overrides are synthetic-profile opt-ins. Why: complete reviews without invented facts or changed tenants.
- White-label CTA hover: WhatsApp may turn green (`wl-visa-cta`); request pop-ups stay brand yellow (`wl-visa-proposal`). Why: green = instant handoff.
- Update prompt: once per user while `app_update_prompt` targets another version. Why: owner-controlled.
- Image library: agency-scoped in SQL, links after service save; hotel photos safe-match on open, confirm ambiguity. Why: no orphans/wrong hotel.
- Bardelli official profile reuses the gold-standard baseline without presentation/demo or unconfirmed blocks, palette via scoped `wl-bardelli-official`; go-live only in `agencySiteStatus`. Why: real tenant never inherits illustrative content.
- Wallet modules: trip > owner agency > system (SQL). Why: isolation.
- Contextual video lessons: `contextual_tutorials` keyed by normalized route (`tutorialContextKey`, ids → `:id`) + per-user `contextual_tutorial_views`; button mounted once in `DashboardLayout`, hidden when a page has no videos. Why: videos without code changes.
- Quote AI pilot (`quote-ai-compose`): off unless secrets `QUOTE_AI_PILOT_ENABLED=true` + caller auth id in `QUOTE_AI_PILOT_ALLOWED_USER_IDS` (roles grant nothing); UI via read-only `status` mode on preview hosts only, pending services in sessionStorage (`quoteAiPending`) applied after quote creation with confirm; quota reserved pre-inference in `daily_feature_usage`, fail closed; PDFs as text only. Why: bounded owner test.

- Universal `/universal` (editorialRose, shared rules/maps) and Disney `/disney` (editorialRose + technical preview host only, simulated submits, no unlicensed hotel photos/ratings). Why: opt-in, preview-safe.
- Site requests: `success:true` required, including duplicates; rejections are retryable errors. Why: no false receipts.
- Resort curation (featured/hidden) lives per agency owner in `agency_resort_settings` (RLS owner-only), edited at `/site/resorts`, read publicly only via SECURITY DEFINER `get_agency_resort_settings(hostname)`; home starts with no state selected and falls back to a random region-balanced sample. Why: tenant isolation, catalog stays global.
- Offer site placement lives in `offers.display_channels` (returned as `channels` by `get_public_offers`); pages filter via `offerInChannel`, and `/oportunidades-novembro` falls back to illustrative cards when none is marked. Why: one offer source, agency picks pages.
- Trip reminder e-mails: daily 07:00 BRT cron → Edge Function `trip-reminder-digest` (cron secret), one digest per agent from `trips` dates; per-user offsets in `trip_email_reminder_settings` (no row = 1 day), sends deduped in `trip_email_reminder_log`. Why: no-miss pre/post-trip follow-up without per-trip jobs.
- Feature usage survey: one row per user in `agent_feature_survey_responses`, modal mounted once in `DashboardLayout`; X opens a retention confirm, "skip" hides it for the browser session (sessionStorage, per user), skipped while impersonating. Why: one answer per agent without blocking urgent work.
